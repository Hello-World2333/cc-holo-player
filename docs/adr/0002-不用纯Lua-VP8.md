# ADR-0002 · 不用纯 Lua 解标准 VP8 / H.264

- 状态：**已接受（这是本项目最重要的一条）**
- 日期：2026-11-15
- 相关：[0001](0001-CC自己解码.md)、[0003](0003-自定义块级码流.md)

## 背景

用户最初的设想是「原视频 → Node → **VP8** → CC（CC 自己解码）→ 屏幕」。
这一条 ADR 记录：**「VP8 码流 + 纯 Lua 解码」在 CC 上不可行**，以及为什么。

## 实测基线

`computer/75/probe3.log`（真机，游戏内 CC，VoidPower hologram）：

```
128x72 (9216 px, 13 rounds): conv perByte=4ms blockwise=1ms
  blit avg=1ms  total(conv blockwise+blit+sync)~3ms
192x108 (20736 px, 5 rounds): conv perByte=11ms blockwise=3ms
  blit avg=3ms  total(conv blockwise+blit+sync)~7ms
256x144 (36864 px, 3 rounds): conv perByte=19ms blockwise=6ms
  blit avg=5ms  total(conv blockwise+blit+sync)~11ms
320x180 (57600 px, 3 rounds): conv perByte=31ms blockwise=10ms
  blit avg=8ms  total(conv blockwise+blit+sync)~18ms
```

推导：

| 量 | 值 |
|---|---|
| 「串→表」（16 字节/批） | **0.17 µs/像素** |
| 一次 `string.byte(s,i,i+15)` + 16 次表写入 | **2.8 µs** |
| blit | 0.14 µs/像素 |
| **Lua 迭代开销（含表读写）** | **≈2.8 µs/次有效迭代** |

20 fps ⇒ 50 ms/帧 ⇒ 扣除事件/收包/必做的转表+blit 后，**留给解码逻辑约 7000–10000 次迭代**。

## 计算

VP8 一帧 320×180（240 个宏块）的解码量：

| 环节 | 量级 |
|---|---|
| 布尔算术解码（每符号多次 bit 读取 + 概率重归一化） | ≈200 符号/宏块 ⇒ **48,000 符号** |
| 每符号 ≈20 次 Lua 迭代 | ≈1,000,000 迭代 |
| 反量化 + 反变换（24 个 4×4 块/宏块） | ≈5,760 次变换，每次 ≈40 迭代 ⇒ 230,000 |
| 帧内/帧间预测（4×4 边界、9 种模式） | ≈500 迭代/宏块 ⇒ 120,000 |
| 环路滤波 | ≈100 迭代/宏块 ⇒ 24,000 |

合计 ≈ **1.3×10⁶ 迭代/帧** × 2.8 µs = **≈3.6 秒/帧**。

> 需要 20 fps ⇒ 目标 50 ms ⇒ **差 70 倍**。
> 即便砍到 160×90（1/4 像素）也只有 ≈1.5 fps；砍到 80×45 才有 6 fps 但已无实用画质。

H.264（CABAC + 更多帧内模式）、VP9、AV1 只会更重，方向一致。

## 决策

**不尝试在纯 Lua 中解码任何标准视频编码器。** 改为自定义的**块级复制 + 整块 raw** 码流（见 ADR-0003）。

## 后果

**好**

- 解码成本降到 O(块)：典型帧 5–10 ms，全变化帧 22–31 ms，**能跑 20 fps**。
- 编解码都能自己写，可位精确校验，可离线回归。

**坏 / 代价**

- **不兼容任何现成编码器/播放器**：`.ccv` 只有本项目能解，无法用 ffmpeg/VLC 验证。
- 压缩率远低于 VP8（VP8 可到 1 Mbps，我们典型 3–8 Mbps；不过相对 raw 的 37 Mbps 仍省 5–10 倍）。
- 没有 DCT 残差 ⇒ 平坦渐变/细节场景会有块状与色带，画质上限低于标准编码器。

## 仍然保留「VP8」的地方

`node/` 的转码器**仍会用 ffmpeg + libvpx 解/转源视频**（读取阶段），
但**输出的不是 VP8 码流**，而是 `.ccv`。VP8 只是「把任意视频变成逐帧 RGB」的工具链之一，
不是传输格式。这一点在命名上要小心：文档里说「VP8」时指的是**输入侧的解码**，不是线上格式。

## 若将来必须用标准编码器

只有一条路：**在 mod 里加原生解码器**（Java/C 侧解 VP8，Lua 只 blit 结果）。
那时码流格式可以保持 `ccv v1` 不变（只是把「解码」换成「问 mod 要像素」），
但会引入「需要装 mod」的依赖，与 ADR-0001 的目标冲突。**当前不采用，记录备查。**
