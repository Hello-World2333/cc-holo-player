# ADR-0003 · 自定义块级码流（块复制 + 整块 raw）

- 状态：**已接受**
- 日期：2026-11-15
- 相关：[0002](0002-不用纯Lua-VP8.md)、[`../01-码流格式.md`](../01-码流格式.md)

## 背景

ADR-0002 得出结论：不能解标准编码器。那么「自定义」的边界在哪？
约束来自实测的迭代成本（2.8 µs/次有效迭代）与每帧 7000–10000 次迭代的余量。

⇒ 解码必须做到 **O(块)**，即「每块做常数次、且都是 C 侧字符串操作 + 一次整表写入」。

## 决策

码流只包含**三种**操作：

| 操作 | 语义 | CC 成本 |
|---|---|---|
| **SKIP**（bitmap 位为 0） | 本块与上一帧相同，屏幕保持不动 | ~0 |
| **MV**（mode=1） | 从**上一帧**按整数位移 `(dx,dy)` 拷 64×64 | 64 次 `string.sub` + 1 次转表 + 1 次 blit |
| **RAW**（mode=2） | 完整 64×64 像素 | 1 次 `string.sub` + 1 次转表 + 1 次 blit |

**明确不要**：熵编码、DCT/残差、亚像素插值、帧内方向预测、环路滤波、可变块大小（首版）。
理由见 `docs/02` §4.2。

## 理由

1. **只有这三种能保持在 O(块)**。任何逐像素预测/变换都会退回 O(像素×k)，重蹈 ADR-0002 的覆辙。
2. **MV 的收益是「少重绘」而不是「省字节」**。在 hologram 上，未被 blit 的区域自然保留上一帧，
   所以「跳过」是真正的零成本——这让静止/平移画面几乎免费。
3. **整数 MV 无插值**：拷贝是纯内存搬移，可用 `string.sub` 在 C 侧完成，不需要 Lua 逐像素。
4. **raw 块整块替换**：没有残差意味着「部分变化」只能整块重发 4096 B。
   在 2×2 的分区下每 quadrant 15 块，全变化 61.5 KB/帧，仍在 128 KB 单消息限制内。

## 两个 profile

| | P1 · 64×64 | P2 · 16×16 |
|---|---|---|
| 块数（320×180 区域） | 15 | 240 |
| 运动粒度 | 粗 | 接近 MPEG-1 |
| 全变化解码成本 | ~22 ms | ~31 ms |
| 全 intra 码率 | 9.2 Mbps | 39 Mbps（靠 MV 压） |

第一版做 **P1**，跑通全链路后再升级 P2。协议已经用 `profile` 字段预留。

## 后果

**好**

- 解码器极小（< 200 行 Lua），可逐行审阅、易位精确校验。
- 编码器也简单（块匹配 + 阈值），无需实现变换/量化/熵编码。
- 调试直观：一帧就是「哪些块、什么模式、什么参数」，可以用十六进制看。

**坏 / 代价**

- 压缩率与画质都明显不如标准编码器（详见 ADR-0002 的「代价」）。
- **生态为零**：没有工具、没有播放器、出问题只能自己查 ⇒ `tools/` 与 `verify` 是必需品，不是附加项。
- 编码器要自己实现块匹配（虽然可以先用穷举 + 早退，离线转码不在乎速度）。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| **MJPEG / 帧内 JPEG**（DCT + 熵编码） | 每像素逐系数解码，成本与 VP8 同量级 ⇒ ADR-0002 |
| **按 8×8 块做「调色板索引」压缩** | 每像素需查表 + 写入，仍是 O(像素)，且省不了多少 |
| **RLE 行程编码** | 解码要逐段跑到 O(像素) 的写表操作；且视频的行程分布差 |
| **只做「差分块」不做 MV**（只发变化块） | 缺少 MV ⇒ 任何平移都会导致全块重发，bandwidth 爆炸 |
| **允许半像素 MV** | 需要插值 ⇒ 每像素多次运算 ⇒ 回到 O(像素) |
| **两级块（64→16 细分）** | 第一版不做，但协议留了扩展位（新增 `mode=3` 即可，见 `docs/01` §8） |

## 兼容性说明

`mode` 字段是 u8，未使用的值（≥3）为将来扩展保留。
CC 遇到未知 `mode` **必须**报错退出（不能画错），由 `HELLO.version` / 后续 `caps` 位协商，
不允许「尽力解析」。

## 证据

- 每像素/每次迭代成本：`computer/75/probe3.log`（见 ADR-0002）
- 现有 tile 结构（16 字节头 + 像素）已在 4 台机器上跑到 20 fps：
  `~/cc-holo-player/cc/render.lua` 的 `applyTiles`，日志 `frames=9000 blits=47874 fails=0 work=7ms`
  ⇒ 证明「整块 raw + 直接 blit」这条路径在真机上是可用的。
- 单 ws 消息上限 128 KB：`config/computercraft-server.toml`（`max_websocket_message = 131072`）
  ⇒ P1 全 intra 61.5 KB/帧 安全。
