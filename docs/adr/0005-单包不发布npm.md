# ADR-0005 · 单包 TypeScript，不发布 npm

- 状态：**已接受**
- 日期：2026-11-15

## 背景

第一版草稿曾提出「pnpm workspace：server / agent / protocol / cc 四个包」，被用户否决：
「分这么老多包是何意味，没让你整这么工程化的，还有我没打算发 npm」。

同时，「CC 自己解码」确定后，**`agent` 这个包根本不存在了**——没有本机代理进程（见 ADR-0001）。

## 决策

`node/` 是**一个** TypeScript 包：

- `package.json` 里 `"private": true`，**永不发布**；
- 不分 workspace、不分内部包、不建 monorepo；
- 模块边界靠**文件**划分（`protocol.ts` / `transcode.ts` / `serve.ts`），不靠包；
- 运行时依赖只有 `ws`（外加外调的 `ffmpeg` 二进制）；
- 构建就是 `tsc`，产物 `dist/`，用 `node dist/serve.js` 跑。

## 理由

1. **只有一个部署目标**（一台 VPS）。多包带来的版本对齐、构建编排、路径解析都是纯开销。
2. **不发布**就没必要维护 `exports` 映射、`files` 白名单、语义化版本。这些都是给「别人 import 你」准备的。
3. 项目规模决定了「协议」只是**一个 200 行的文件**，不值得一个包。
4. CC 端是 **Lua**，本来就不可能和 TS 共享包——「多包共享协议」这个收益在跨语言下并不存在，
   `docs/01` 的文档才是唯一的契约。

## 后果

**好**

- `git clone && npm i && npm run build` 就能跑，没有 pnpm、没有 turbo、没有 link。
- 文件引用直接 `import { ... } from "./protocol.js"`，出错时栈里是真实路径。
- 依赖树极浅（只有 `ws` + devDeps `typescript`），VPS 上装得快、审计简单。

**坏 / 代价**

- 将来若真要把 `protocol` 复用到别处（例如 mod 里的 Java 实现），会有「复制还是抽包」的选择。
  **届时的答案**：先复制，等出现第三处再抽——现在是第一处。
- 没有 workspace 就没有「一次构建全部」；但项目只有一个包，这不成问题。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| pnpm workspace 四包 | 过度工程；`agent` 包随 ADR-0001 一起消失 |
| 单包但发布到 npm | 用户明确不做；无消费者 |
| 用 Rust/Go 写解码侧单文件二进制 | 部署到 MC 机器省依赖的诉求随 ADR-0001 消失；公网侧 TS + ffmpeg 足够 |
| 用 ffmpeg.wasm / fluent-ffmpeg | 多一层封装、多一个依赖，排障更难；直接 `spawn ffmpeg` 最直白 |

## 证据

- 用户原话（2026-11-15）：「分这么老多包是何意味 没让你整这么工程化的 还有你想哪去了 agent是啥包。还有我没打算发npm」
- 目录实测：`node/` 规划只有 5 个源文件 + 1 个 `package.json`（见 `node/README.md`）。
