# cc-video-wall

CC（ComputerCraft）全息视频墙：**公网 Node 负责编码，游戏里的 CC 电脑自己解码，画到 VoidPower 的 hologram 上**。
多块屏幕可拼接成更高的分辨率。

> 状态：**设计阶段**。本仓库目前只有文档和目录骨架，没有实现代码。
> 动手前请先读 [`docs/02-解码预算与编解码器.md`](docs/02-解码预算与编解码器.md)——
> 那里有一条硬约束（CC 的 Lua 每像素约 0.17µs），它决定了整个项目的形态。

## 它是什么

```
┌──────────────┐   原视频(mp4/任意)    ┌────────────────┐
│ 公网服务器    │ ────────────────────▶ │ 转码器 (离线)   │  →  .ccv 文件
│ Node         │                       └────────────────┘
│              │   wss 推码流（几十~几百 KB/s）
└──────┬───────┘
       │ 公网
┌──────▼───────────────────────────────────────────────┐
│ MC 服务器（另一台机器）——**不装任何东西**             │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐    │
│  │ CC #A   │ │ CC #B   │ │ CC #C   │ │ CC #D   │    │
│  │ 解左上一 │ │ 解右上  │ │ 解左下  │ │ 解右下  │    │
│  └────┬────┘ └────┬────┘ └────┬────┘ └────┬────┘    │
│       │  fabric（同步/控制，几字节/帧）     │         │
│       └───────────┴─────┬─────┴───────────┘         │
│                  ┌──────▼──────┐                     │
│                  │  hologram   │ 640×360 一张屏      │
│                  └─────────────┘                     │
└──────────────────────────────────────────────────────┘
```

要点：

1. **MC 那台机器零依赖**：不需要 node、不需要 ffmpeg、不需要本地代理进程。码流直接从公网进 CC 的 `http.websocket`。
2. **编码在公网、解码在 CC**：所以传的是压缩码流（几十~几百 KB/s），不是 rawvideo（640×360@20fps raw = 37 Mbps）。
3. **fabric 只跑控制**：帧号栅栏、播放状态、按键。像素不走 fabric——fabric 每个发送机每 tick 只有 8 条大包的额度（≈1.15 MB/s），喂不动一块屏。
4. **多屏拼接**：画面按 quadrant 切成独立码流，各机只解自己那一块；写的是**同一张** hologram 缓冲的不同坐标。

## 与已有项目的关系

- [`~/cc-holo-player`](../cc-holo-player/) 是**上一代**：单机 master + 4 台 raw 瓦片渲染机 + 宿主机 Node 实时转码，raw 走 CC 的 ws。
  本项目的区别是：**把解码搬进 CC**（因此 MC 侧零依赖、可跨公网）、**码流是压缩的**、**多屏可配**。
- 它的实测数据（全息 blit 成本、事件被吞、framebuffer 泄漏、CC ws 限额）在本仓库直接沿用，见 `docs/02` 与 `docs/03` 的引用。
- 上游模组文档：`~/worker-docs/void-power-mod/`（hologram API）、`~/worker-docs/cee-cc/`（CEE:CC 的 `cee.*`，取外设/音响用）。
